The motto I go by

Validate before anything else.

When I'm troubleshooting something with a lot of unknowns, I run the same three checks before I trust that it's actually fixed — assuming it's already handled is how it fails again once it's in production.

1

Check the config

Confirm what was actually applied to the device — not what was intended, what's actually sitting there.

2

Capture the traffic

Watch what's actually happening on the wire before guessing why something's behaving the way it is.

3

Compare against documentation

If something still doesn't add up, cross-check it against the spec before assuming it's the platform's fault, or yours.

D2EMUX: my first project on SAOS 10.x

Completed
Platform: D2EMUX white boxOS: SAOS 10.x
Disaggregated white-box switches — the hardware class D2EMUX belongs to

D2EMUX was my introduction to Ciena's SAOS 10.x architecture — a real departure from the SAOS 6.x devices I'd worked on before. I tested and certified gNMI telemetry sensors, configuration RPCs, end-to-end traffic passing, and the migration to Ciena's Trusted Partner Licensing Model (TPLM).

The TPLM piece is the part I'd point to first: previously, a device had to check back in with a license server roughly every week to stay licensed. TPLM replaces that with a license that's verified once and then persists permanently — surviving even a factory reset. Certifying it meant proving that held up under the edge cases that actually matter in production, not just the happy path.

I also owned the documentation for it end to end: an Integration Guide for external integrators, covering everything that changed from the previous phase, and a separate production Deployment Guide — two different audiences, written from the same validation work.

Working across platforms

Different vendors, different eras, different ways of thinking about the same underlying network.

Beyond Ciena, I've worked hands-on with Juniper and Cisco — and within Ciena alone, SAOS 6.x and SAOS 10.x differ enough in CLI structure and configuration architecture that they function almost like separate skill sets. Rather than specializing narrowly in one vendor's syntax, I've had to repeatedly re-orient to new command paradigms and pick them up quickly. That matters more as networks get more heterogeneous, not less.
